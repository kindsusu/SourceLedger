# 브라우저 인증 복구

[English](BROWSER_RECOVERY.md)

SourceLedger는 인식 가능한 접근 확인 화면을 감지하고 **연결된 AI의 브라우저 지원 절차**를 준비한다. 자체 CAPTCHA 해결기·유료 해결 서비스·AI 대화 자동 시작·쿠키 전송 기능은 없다. 실제 조작 가능 여부는 연결 앱의 도구와 정책에 달려 있으며 인증 성공을 보장하지 않는다.

## 사용 흐름

1. CAPTCHA를 감지하면 `blocked`와 `access_challenge`를 기록한다. 해당 페이지의 자동 백엔드 전환·일시 오류 재시도를 중지한다. 이전 안전한 캡처는 보존하고 인증 화면을 가격으로 추출하지 않는다. 다른 대상은 기존 작업 예산 안에서 계속 처리한다.
2. UI에서 **브라우저 지원 준비**를 누르면 연결 AI에 전달할 지시문이 표시된다. 준비만으로 AI가 실행되거나 시도 횟수가 차감되지는 않는다. MCP 연결 AI에서는 `prepare_browser_recovery`를 직접 호출한다.
3. 앱의 브라우저와 인증 화면 조작이 지원되면 `begin_browser_recovery`로 1회 시도를 예약한 뒤 승인된 페이지에서 조작한다. 지원되지 않으면 사용자에게 인증을 요청한다.
4. 반환된 `attempt_id`로 `finish_browser_recovery`를 호출해 차단 지속·사용자 필요·접근 가능을 기록한다. 접근 가능 보고에는 승인된 정확한 URL과 실제 대상 화면의 짧은 원문이 필요하다. 체크박스만으로 성공 처리하지 않으며 비밀번호·인증정보를 제출하지 않는다.
5. 통과한 AI 브라우저의 같은 탭에서 증거 수집을 이어간다. 단일 조사 작업은 `submit_browser_evidence`로 제출할 수 있다. 배치 결과는 해당 제출 경로를 지원하지 않아 검토한 후속 조사 계획이 필요하다. 접근 성공 보고는 독립 검증이 아니며 기존 이슈를 자동 해결하거나 가격을 생성하지 않는다.

원본 실행·정확한 URL별 최대 2회이며 재시작·지시문 재생성으로 초기화되지 않는다. 진행 중 예약은 같은 ID를 반환하고, 완료된 결과는 덮어쓸 수 없다. 사용자 필요 또는 접근 가능 보고 후에는 해당 실행의 추가 자동 시도를 막는다. 중단된 시도는 결과 기록 전까지 예약 상태를 유지한다. 새 실행을 반복해 시도 제한을 우회하는 용도로 사용하지 않는다.

서버 수집기는 AI 앱의 로그인 세션을 이어받지 않는다. 기존 권한 있는 로컬 프로필로 서버 재수집하려면 계획의 수집 규칙을 수정·검토·승인해야 한다. Codex·Claude 탭을 Playwright로 옮기는 원클릭 재개는 지원하지 않는다. UI도 지시문 생성만으로 접근 복구·문제 해결을 표시하지 않는다.

## 검증 범위

오프라인 테스트로 HTTP 200 인증 화면, 일반 상품·문의 폼의 오탐 방지, 차단 처리, 이전 캡처 보존, 시도 횟수 영속성, MCP 호출, 보호된 로컬 Web API를 검사한다. 모든 제공자·맞춤 화면·JavaScript 상태를 감지하는 것은 아니며, 미확인 접근 실패는 확인할 이슈로 남긴다.

2026-10-14의 이전 오프라인 검증: 관련 연동 검사 99개가 통과했고 클립보드 모의 테스트 1개가 실패했다. 모의 설정을 수정한 뒤 UI 검사 5개가 모두 통과했다. 최종 감지·복구 검사 29개가 통과했으며, localhost의 Playwright 페이지에서 옵션 수집 후 CAPTCHA로 전환되는 경우도 포함한다. 중복된 검사이므로 합산하지 않는다. Python 컴파일·Git 공백 검사도 통과했다.

2026-10-14 실제 검증에는 연결된 Codex 브라우저를 사용했다. Google 공식 reCAPTCHA 데모에서 승인된 체크박스 시도 1회로 체크 표시가 나타났고, 일반 양식을 제출하자 서버의 성공 메시지가 표시됐다. 이미지 선택 문제는 나오지 않았다. 제트카·공카 상품 페이지에는 CAPTCHA가 없었다. Google 데모에 대한 SourceLedger HTTP 수집은 사이트 규칙에 따라 `robots_disallowed`에서 중단했다. 로컬 stdio MCP의 `initialize`/`list_tools`로 복구 도구 3개의 노출을 확인했으나 복구 호출은 하지 않았다. 유료 API는 사용하지 않았다.

실제 상품 사이트의 차단 이슈가 발생하지 않아 전체 복구 흐름, 같은 탭의 증거 제출, 접근 복구는 검증하지 못했다. 이미지·음성 문제, 다른 제공자, Claude 브라우저 호스트도 시험하지 않았다. 데모 통과만으로 SourceLedger의 차단 소스 복구를 검증한 것은 아니다.
