# 수집 신뢰성

최근 범위 판정·체크포인트 개선은 [2026-10-14 구현 결과](CROSS_SITE_RELIABILITY_2026-10-14.ko.md)를 참고하세요.

SourceLedger는 관측을 그 값을 만든 원문과 조건에 연결합니다. SQLite에는 출처 자료와 이력을, XLSX에는 사람이 읽는 보고서를 기록합니다. XLSX는 보존한 증거를 대체하지 않습니다.

## 연구 범위와 지원 페이지

`source-ledger init`으로 시작합니다. 워크스페이스는 수집 전에 산업군·상품·대상 시장을 묻습니다. 이후 `collect-sites`는 지원되는 Jetcar, Gongcar, Funrent 형식의 명시적이고 권한 있는 URL만 받습니다.

```powershell
source-ledger collect-sites `
  --url "https://www.jetcar.kr/sub0201/<vehicle-id>" `
  --max-pages 5 --max-seconds 120
```

이 명령은 `init`이 만드는 기본 워크스페이스 `.sourceledger/research.json`을 사용하며, 별도 주제일 때만 `--workspace PATH`를 지정합니다. 조건부 수집을 끄려면 `--no-incremental`을 사용합니다. 사용자가 넣은 지원 상세 페이지 또는 렌더링 계산기 페이지만 정해진 페이지·시간 한도 안에서 수집하며 견적 양식을 제출하지 않습니다. 사이트의 모든 목록을 탐색하지 않고, 선택하지 않은 페이지의 값을 추정하지 않으며, 사이트 전체 재고 범위를 보장하지 않습니다. 이 흐름은 유료 MCP 서비스를 사용하지 않습니다.

## 가격 프로필, 값의 출처, 조건

`Product.price_profile`은 `unit` 또는 `rental`입니다. `unit`은 일반 상품 가격 비교 규칙을 유지합니다. `rental`은 견적 조건을 근거가 있는 필드로 보존합니다. `deposit_amount`, `advance_amount`, `deposit_installment_amount`, `deposit_installment_months`는 서로 다른 조건입니다. 수집기는 이 값을 더하거나 빼거나 서로 대신 넣지 않습니다.

지원하는 `Source.adapter` 값은 `jetcar`, `gongcar`, `funrent`입니다. 이름이 지정된 렌더링 형식에 대한 결정적 파서이며, 원문 HTML과 브라우저 상태는 증거로 남습니다. 추출기는 출처 스크립트를 실행하지 않지만, 브라우저 backend는 검토한 페이지 상태를 렌더링하기 위해 페이지의 일반 JavaScript를 실행할 수 있습니다.

- `observed`는 출처 화면에 표시되고 근거로 뒷받침된 값입니다.
- `calculator_estimate`는 화면의 계산기 출력입니다. 이는 추정값으로 남으며 관측 가격이나 비교 가능한 단가 견적으로 바뀌지 않습니다.
- 렌탈 견적이 비교 가능하려면 `visible`이어야 합니다. 숨김 내용, 누락·충돌·불완전한 근거는 비교 대신 검토 대상으로 보존합니다.

## 보고서의 증거와 비교

실행에 렌탈 관측이 있으면 XLSX에 **Rental Quotes** 시트를 추가합니다. 관측 월 납입금과 계산기 추정값은 다른 열에 두고, 보증금·선납금·보증금 할부도 서로 다른 조건으로 보존합니다. 렌탈 관측이 없는 실행에는 이 시트를 만들지 않습니다.

**Observation History**는 관측·추정 금액을 나누어 원문 필드, 필드별 근거, 값의 출처, 화면 표시 상태, 검증 수준, 파생 값, 렌탈 조건과 함께 보존합니다. 가격 비교 통계에는 확인된 화면 표시 관측값만 넣으며 계산기 추정값과 숨겨진 출처 값은 넣지 않습니다.

## 조건부 수집과 추출 재사용

원시 또는 정적 HTTP HTML의 가격은 계산된 CSS 표시 상태를 증명하지 못하므로 어댑터가 `unconfirmed`로 기록합니다. 가격은 보존하지만 화면 표시 근거를 캡처할 때까지 비교에는 넣지 않습니다. 구조화 파일과 문서 기록에는 이 규칙이 적용되지 않습니다. HTML 표시 근거가 부족하면 수집기가 증거 캡처를 재시도할 수 있으나, 거래 조건이 없다는 이유만으로 무한 재시도하지 않습니다. Playwright 캡처는 계산된 숨김 상태를 보존합니다. `verified`는 원문 필드 검증을 뜻하며, 계약 조건이 부족하면 여전히 비교할 수 없습니다. 충돌한 관측 금액도 원장에 유지합니다. 이력에는 미검증 관측 금액 열을 별도로 두고, Rental Quotes에서는 검토 상태·사유와 함께 금액을 표시합니다. Source Evidence는 캡처된 스크린샷·receipt 참조를 기록합니다.

일반 `Source.incremental`은 `"incremental": true`를 명시할 때만 켜집니다. `collect-sites`는 생성하는 공개 HTTP 출처에 기본으로 켜며, 이 명령에서 끄려면 `--no-incremental`을 사용합니다. 증분 수집은 적격 공개 HTTP 웹 출처에만 적용하며, 브라우저 레시피 또는 프로필이 있는 출처, 내부 출처, 공개가 아닌 계정 범위, 파일, 브라우저 수집에는 적용하지 않습니다.

적격 출처는 ETag와 Last-Modified 메타데이터를 보존할 수 있습니다. 다음 실행도 반드시 출처에 요청하며, 일치하는 HTTP `304 Not Modified` 응답이 있을 때만 기존 본문과 추출 결과를 재사용합니다. 이 경우에도 새 실행에서 날짜 기반 유효성을 포함해 후보를 다시 검증합니다. 새로 받은 본문이 동일하면 추출을 재사용할 수 있지만, 본문이 바뀌면 다시 추출합니다.

validator를 보내기 전에 증거가 워크스페이스 evidence 디렉터리 안에 있고 읽을 수 있으며 해시가 일치하는지 확인합니다. 증거가 없거나 바뀌면 validator 없이 새로 요청합니다. 출처 규칙, 레시피 버전, 계정 범위, 어댑터·추출기 코드, 그 밖의 캐시 키 대상 설정이 바뀌어도 새 요청을 합니다. 따라서 캐시 본문을 새로 수집한 것처럼 표시하지 않으며, 새 수집 또는 검증된 조건부 응답이 있을 때만 재사용합니다.

## 접근과 브라우저 증거

조사 계획 갱신에는 기존 수집 체크포인트, 영속 이슈 기록, 브라우저 복구, 적격 HTTP validator를 재사용합니다. 새 계획의 기본값은 `incremental`과 `full_interval_days: 7`이며 검토 후 `full` 또는 1~365일 간격을 선택할 수 있습니다. 첫 실행, 기한 도래, 규칙 변경, 유효하지 않은 기준선은 다음 실행을 전체 재확인으로 만듭니다. 기한은 실행 시 판단하며 시간이 지났다는 이유만으로 예약 실행하지 않습니다. 갱신 정책이 없는 기존 확정 계획은 전체 수집을 유지합니다. 브라우저 페이지는 다시 방문해야 하며 기존 세션·캡처를 자동 재사용하지 않습니다.

갱신 비교는 승인한 URL과 실제 방문한 페이지에 한정합니다. URL별 상세 변경은 SQLite에 보존하고 XLSX에서 사람이 검토할 수 있으며 MCP 결과에는 최대 50개 항목만 요약합니다. 추가·변경·동일·접근 불가·삭제 후보를 구분합니다. 삭제 후보는 이전과 현재의 페이지 목록이 모두 완전할 때만 표시하며 차단·불완전 페이지는 접근 불가로 남깁니다. 같은 호스트의 링크 발견은 사이트 전체의 완전성을 증명하지 않으며 없는 가격·통화·식별자·거래 조건을 추정하지 않습니다.

실행 중 확인된 CAPTCHA·접근 확인과 인증 요구는 MCP 진행 상태에 제한된 확인 항목으로 나타나며 UI에는 수집을 막지 않는 알림과 확인 목록으로 표시됩니다. 일반 HTTP 403이나 정책 거부만으로 브라우저 인계 알림을 만들지 않습니다. 다른 URL은 계속 처리하고 차단된 페이지는 누락 범위에 남깁니다. 링크를 열어도 사용자 브라우저 세션이 수집기로 이전되거나 이슈가 자동 해결되지 않으며 명시적 근거 제출과 분류 절차를 따라야 합니다.

URL 정책 거부는 잘못된 URL, URL 내 자격증명, 허용 도메인 밖 주소, DNS 해석 실패, 사설 주소, 특수 목적 주소에 안정적인 진단 코드를 사용합니다. 외부에 보이는 진단에는 쿼리 값, 자격증명, 쿠키, DNS 오류 상세를 넣지 않습니다. robots 404/410은 규칙이 없는 경우이고 인증·접근 오류는 규칙 부재로 처리하지 않고 사용할 수 없는 상태로 남깁니다. HTTP 403과 429도 각각 접근 차단과 속도 제한으로 구분해 기록합니다.

브라우저 레시피는 설정된 click, select, fill, wait, assert 동작만 할 수 있고 읽기 전용 용도로 검토합니다. 수집기는 네이티브 양식 제출을 막지만, 페이지 JavaScript의 다른 요청까지 전부 막는다고 보장하지는 않습니다. 브라우저 증거는 select·checkbox·radio의 현재 선택 상태를 정리한 HTML 스냅샷, 스크린샷, 안전한 컨트롤 label trace로 남깁니다. 정리는 캡처한 form input·textarea 값을 제거합니다. 페이지 HTML의 다른 위치에 있는 모든 쿠키·토큰·연락처·스크립트 제공 값을 완전히 제거한다고 보장하지는 않습니다.

구현 범위와 경계는 [Milestone 04](MILESTONE_04.md)를 참고하세요.

펀렌트카의 차량 미선택 상태는 누락 사유로 남습니다. 공카는 Codex 브라우저에서

### 갱신 방식 선택

전체·변경분 모드 모두 현재 관측과 마지막 정상 기준의 변경 내역을 제공합니다. 변경분 모드는 유효한 보존 증거가 있는 적격 HTTP 출처에서 전송·추출 작업을 줄일 수 있지만, 동적 페이지의 변경 여부를 방문 없이 알아내지는 못합니다. 브라우저 중심 대상은 동일 목록 실측에서 이점이 확인되기 전까지 전체 모드를 선택하세요. 결과를 비교하는 것 자체가 속도 개선은 아닙니다.

카탈로그 HTTP 추출 재사용에는 본문·최종 URL·자료 형식·출처 설정·추출 규칙의 일치가 필요합니다. 원시 후보를 복원한 뒤 현재 범위 필터와 검증을 다시 적용합니다. 추출 오류는 명시적인 실패이며 마지막 정상 비교 기준이나 성공한 전체 확인 시각을 덮어쓰지 않습니다. 다른 응답에서 일부 관측을 보존했더라도 실패한 페이지는 누락으로 남습니다.

브라우저 작업자 전체에 공통 15초 종료 유예를 적용합니다. Chromium의 정상 종료가 2초를 넘었다는 이유로 수집을 실패 처리하지 않습니다. 유예 후에도 살아 있는 작업자는 계속 오류이며 중복 재시도나 분리된 브라우저를 완료로 처리하지 않습니다.

### 선택적 화면 닫기

검토된 `click` 레시피에 `if_visible: true`를 지정할 수 있습니다. 보이는 대상이 없으면 건너뛴 단계로 기록하고, 하나일 때만 클릭하며, 여러 개면 실패로 처리합니다. 공카의 읽기 전용 요금표를 열기 전에 알려진 홍보 팝업을 닫는 데 사용합니다. 견적 양식을 제출하거나 CAPTCHA·인증 확인을 건너뛰는 기능은 아닙니다.


### 현재 공카 요금표

기존 렌트 경로와 현재 `/monthly`·`/daily` 리다이렉트를 함께 지원합니다. 장기렌트·렌트패스·월렌트는 보이는 전체 요금표를 열어 기간과 결제 조건별 표시 칸을 각각 추출합니다. 선언된 차종 수와 보이는 차량 그룹 수를 대조하며 숨김·누락·미해석 칸이 있으면 부분 수집으로 남깁니다. 문의만 표시된 칸은 가격 없는 관측으로 보존합니다. 시작 가격 카드는 `부터`라는 의미와 검토 상태를 유지하고 상세 요금표를 대신하지 않습니다.

고유한 원문 `data-id`가 있으면 조건별 식별에 사용합니다. 식별자가 없거나 중복되면 불확실성을 표시한 로컬 관측으로 남깁니다. 공개 요금표가 차량 재고나 계약 가능한 확정 견적을 보장하지는 않으며 원문 날짜·상업 조건을 관측에 연결합니다.
