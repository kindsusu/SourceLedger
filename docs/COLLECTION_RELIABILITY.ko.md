# 수집 신뢰성

SourceLedger는 관측을 그 값을 만든 원문과 조건에 연결합니다. SQLite에는 출처 자료와 이력을, XLSX에는 사람이 읽는 보고서를 기록합니다. XLSX는 보존한 증거를 대체하지 않습니다.

## 연구 범위와 지원 페이지

`source-ledger init`으로 시작합니다. 워크스페이스는 수집 전에 산업군·상품·대상 시장을 묻습니다. 이후 `collect-sites`는 지원되는 Jetcar, Gongcar, Funrent 형식의 명시적이고 권한 있는 URL만 받습니다.

```powershell
source-ledger collect-sites --workspace .sourceledger/workspace.json `
  --url "https://www.jetcar.kr/sub0201/<vehicle-id>" `
  --max-pages 5 --max-seconds 120
```

이 명령에서 조건부 수집을 끄려면 `--no-incremental`을 사용합니다. 사용자가 넣은 지원 상세 페이지 또는 렌더링 계산기 페이지만 정해진 페이지·시간 한도 안에서 수집하며 견적 양식을 제출하지 않습니다. 사이트의 모든 목록을 탐색하지 않고, 선택하지 않은 페이지의 값을 추정하지 않으며, 사이트 전체 재고 범위를 보장하지 않습니다. 이 흐름은 유료 MCP 서비스를 사용하지 않습니다.

## 가격 프로필, 값의 출처, 조건

`Product.price_profile`은 `unit` 또는 `rental`입니다. `unit`은 일반 상품 가격 비교 규칙을 유지합니다. `rental`은 견적 조건을 근거가 있는 필드로 보존합니다. `deposit_amount`, `advance_amount`, `deposit_installment_amount`, `deposit_installment_months`는 서로 다른 조건입니다. 수집기는 이 값을 더하거나 빼거나 서로 대신 넣지 않습니다.

지원하는 `Source.adapter` 값은 `jetcar`, `gongcar`, `funrent`입니다. 이름이 지정된 렌더링 형식에 대한 결정적 파서이며, 원문 HTML과 브라우저 상태는 증거로 남습니다. 추출기는 출처 스크립트를 실행하지 않지만, 브라우저 backend는 검토한 페이지 상태를 렌더링하기 위해 페이지의 일반 JavaScript를 실행할 수 있습니다.

- `observed`는 출처 화면에 표시되고 근거로 뒷받침된 값입니다.
- `calculator_estimate`는 화면의 계산기 출력입니다. 이는 추정값으로 남으며 관측 가격이나 비교 가능한 단가 견적으로 바뀌지 않습니다.
- 렌탈 견적이 비교 가능하려면 `visible`이어야 합니다. 숨김 내용, 누락·충돌·불완전한 근거는 비교 대신 검토 대상으로 보존합니다.

## 보고서의 증거와 비교

실행에 렌탈 관측이 있으면 XLSX에 **Rental Quotes** 시트를 추가합니다. 관측 월 납입금과 계산기 추정값은 다른 열에 두고, 보증금·선납금·보증금 할부도 서로 다른 조건으로 보존합니다. 렌탈 관측이 없는 실행에는 이 시트를 만들지 않습니다.

**Observation History**는 관측·추정 금액을 나누어 원문 필드, 필드별 근거, 값의 출처, 화면 표시 상태, 검증 수준, 파생 값, 렌탈 조건과 함께 보존합니다. 가격 비교 통계에는 확인된 화면 표시 관측값만 넣으며 계산기 추정값과 숨겨진 출처 값은 넣지 않습니다.

## 조건부 수집과 추출 재사용

정적 HTTP HTML은 계산된 CSS 표시 상태를 증명하지 못하므로 어댑터가 `unconfirmed`로 기록합니다. Playwright 캡처는 계산된 숨김 상태를 보존합니다. `verified`는 원문 필드 검증을 뜻하며, 계약 조건이 부족하면 여전히 비교할 수 없습니다. 충돌한 관측 금액도 원장에 유지합니다. 이력에는 미검증 관측 금액 열을 별도로 두고, Rental Quotes에서는 검토 상태·사유와 함께 금액을 표시합니다.

일반 `Source.incremental`은 `"incremental": true`를 명시할 때만 켜집니다. `collect-sites`는 생성하는 공개 HTTP 출처에 기본으로 켜며, 이 명령에서 끄려면 `--no-incremental`을 사용합니다. 증분 수집은 적격 공개 HTTP 웹 출처에만 적용하며, 브라우저 레시피 또는 프로필이 있는 출처, 내부 출처, 공개가 아닌 계정 범위, 파일, 브라우저 수집에는 적용하지 않습니다.

적격 출처는 ETag와 Last-Modified 메타데이터를 보존할 수 있습니다. 다음 실행도 반드시 출처에 요청하며, 일치하는 HTTP `304 Not Modified` 응답이 있을 때만 기존 본문과 추출 결과를 재사용합니다. 이 경우에도 새 실행에서 날짜 기반 유효성을 포함해 후보를 다시 검증합니다. 새로 받은 본문이 동일하면 추출을 재사용할 수 있지만, 본문이 바뀌면 다시 추출합니다.

validator를 보내기 전에 증거가 워크스페이스 evidence 디렉터리 안에 있고 읽을 수 있으며 해시가 일치하는지 확인합니다. 증거가 없거나 바뀌면 validator 없이 새로 요청합니다. 출처 규칙, 레시피 버전, 계정 범위, 어댑터·추출기 코드, 그 밖의 캐시 키 대상 설정이 바뀌어도 새 요청을 합니다. 따라서 캐시 본문을 새로 수집한 것처럼 표시하지 않으며, 새 수집 또는 검증된 조건부 응답이 있을 때만 재사용합니다.

## 접근과 브라우저 증거

URL 정책 거부는 잘못된 URL, URL 내 자격증명, 허용 도메인 밖 주소, DNS 해석 실패, 사설 주소, 특수 목적 주소에 안정적인 진단 코드를 사용합니다. 외부에 보이는 진단에는 쿼리 값, 자격증명, 쿠키, DNS 오류 상세를 넣지 않습니다. robots 404/410은 규칙이 없는 경우이고 인증·접근 오류는 규칙 부재로 처리하지 않고 사용할 수 없는 상태로 남깁니다. HTTP 403과 429도 각각 접근 차단과 속도 제한으로 구분해 기록합니다.

브라우저 레시피는 설정된 click, select, fill, wait, assert 동작만 할 수 있고 읽기 전용 용도로 검토합니다. 수집기는 네이티브 양식 제출을 막지만, 페이지 JavaScript의 다른 요청까지 전부 막는다고 보장하지는 않습니다. 브라우저 증거는 select·checkbox·radio의 현재 선택 상태를 정리한 HTML 스냅샷, 스크린샷, 안전한 컨트롤 label trace로 남깁니다. 정리는 캡처한 form input·textarea 값을 제거합니다. 페이지 HTML의 다른 위치에 있는 모든 쿠키·토큰·연락처·스크립트 제공 값을 완전히 제거한다고 보장하지는 않습니다.
