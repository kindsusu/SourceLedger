# 구현 상태

이 문서는 현재 코드가 제공하는 기능과 아직 제공하지 않는 기능을 구분합니다.

## 구현됨

| 영역 | 동작 |
| --- | --- |
| 설정 범위 | 제품 식별자와 출처 URL/파일을 사전에 설정한다. 웹 URL은 허용 도메인, 내부 자료는 local file/file_root 또는 권한 있는 internal 웹 출처로 제한한다. |
| 수집 | HTTP, 로컬 파일, 선택적 Playwright/Crawl4AI backend를 사용한다. profile_dir의 로그인된 전용 브라우저 상태를 재사용할 수 있지만 로그인 절차는 자동화하지 않는다. 상태·시도 횟수·실패 사유를 실행 DB에 기록한다. |
| 추출 | HTML CSS selector, CSV/XLSX 열, JSON 객체/배열, PDF 텍스트 정규식의 명시 규칙만 사용한다. 스캔 PDF OCR은 미구현이다. |
| 검증 | 원문 식별자·가격·통화·증거 위치를 확인한다. `price_basis`(pack/each)와 비교 조건이 부족한 `verified` 행은 `comparable=false`다. 가격 기준 근거가 없으면 정규화 단가를 계산하지 않는다. 유효기한은 수집·재출력 시점에 검사하며, 수집 당시 품절인 관측도 비교에서 제외한다. 재출력만으로 현재 재고를 다시 확인하지는 않는다. |
| 증거 | 응답 원문, 수집 receipt, SHA-256, 로케이터와 원문 값을 보존한다. |
| 재개/보고 | 실행 ID로 미종료 작업을 재개하고, 근거 중심 XLSX 6개 시트를 생성한다. |
| 진단 | `su-crawler doctor`가 로컬 backend와 선택 의존성의 설치 상태를 보고한다. |
| URL 후보 발견 | `discover --source-id ... --limit ...`가 설정된 HTML 링크 또는 XML sitemap에서 허용 도메인 안의 후보 URL을 bounded하게 반환한다. 후보는 가격 근거가 아니며 자동 설정 추가·자동 학습을 하지 않는다. |

## MCP 운영 모델

MCP는 고정 설정을 읽어 작업 등록과 조회를 제공하는 로컬 제어면입니다. 수집 실행은 MCP가 child process를 만들지 않고 별도 정상 터미널의 worker가 담당합니다. Windows 클라이언트 Job Object 종료 시 child worker도 함께 종료될 수 있기 때문입니다.

1. 운영자가 `python -m su_crawler.worker --config <설정>`으로 독립 worker를 시작합니다.
2. heartbeat가 살아 있는 경우에만 MCP의 수집 시작 요청을 받습니다. heartbeat가 없으면 시작을 거절합니다.
3. `su-crawler serve-mcp --config <설정>`은 기본 stdio transport로 MCP 클라이언트에 연결됩니다.
4. `--transport streamable-http`은 `127.0.0.1`만 bind합니다.

MCP는 실행 결과를 인터넷에 업로드하거나 원격 다운로드 URL을 만들지 않습니다. 원격 ChatGPT에서 사용하려면 인증된 배포, 접근 제어, XLSX/증거 파일의 다운로드 경로를 별도로 구성해야 합니다.

독립 worker를 서비스로 등록하거나 일정에 따라 상시 실행하는 기능은 아직 없습니다. 운영자가 정상 터미널에서 worker를 실행하는 모델만 지원합니다.

## 실제 확인한 검증

2026-09-16, Windows/Python 3.12에서 `python -m pytest tests -q` 결과 **44 passed**.

- 실제 로컬 Chrome으로 시험 페이지의 옵션 선택·클릭·가격 문구 확인·스크린샷 저장을 실행했다. 이 시험은 외부 사이트의 AI 차단 해제를 입증하지 않는다.
- MCP SDK로 실제 stdio 서버에 연결해 작업을 등록했다. HTTP 응답이 대기 중일 때 MCP 클라이언트/서버를 종료하고, 독립 worker가 계속 수집해 보고서를 만드는 것을 확인했다. 새 MCP 세션에서 상태·관측·재출력도 확인했다.
- 원문 없는 가격, 통화 상충, 규격 불일치, 빈값·0 구분, 근거 값 불일치, 가격 기준 누락, 만료·품절, 단가 계산, 정밀도 보존을 검사했다.
- 합성 HTML/내부 CSV 데모에서 예정 작업 5개, 관측 4개, 확인 가격 2개를 기록했다. 가격 문의·빈가격·상품 미발견을 남기고 `partial`로 완료했다. 합성 가격은 실제 시장 가격이 아니다.
- 생성된 XLSX를 artifact-tool로 읽고 6개 시트를 렌더했다. 빈값이 실제 빈 셀로 저장되는지, 확인 가격과 별도 단가 계산, 누락 상태, 테스트 자료 배너를 확인했다. 이후 출력 형식 수정 관련 보고서 테스트 2개와 CLI 변경 관련 MCP 테스트 3개도 통과했다.
- 실사이트 정확도·수집 성공률, Claude/ChatGPT 화면에서의 연결, 유료 UWS 작업 실행은 검증하지 않았다.

## 운영 시 확인할 것

- `doctor` 결과는 설치 가능성만 보여 주며, 대상 사이트 수집 성공을 보장하지 않습니다.
- 수집 전 대상 사이트의 접근 권한, 약관, robots 정책, rate limit을 확인해야 합니다.
- 가격 비교 시트의 숫자는 원문 근거가 있는 관측만 사용합니다. `review`, `price_unavailable`, `stale`, `unknown` 행을 비교 수치로 해석하면 안 됩니다.
- `price_basis`와 포장 수량의 원문 근거가 없으면 정규화 단가가 비어 있는 것이 정상입니다. 해당 값을 추정해 채우면 안 됩니다.
- 데모 설정과 보고서의 배너는 테스트 자료임을 표시하며 실제 시장 가격 근거가 아닙니다.
- 보고서는 실행별 결과입니다. 여러 실행을 합친 월별 추이와 현재 재고 확인은 별도 재수집·집계가 필요합니다.

## 실제 도입 전 필요한 자료

| 자료 | 용도 |
| --- | --- |
| 산업 상품 SKU/모델 목록 | 상품 식별자와 비교 단위를 고정한다. |
| 실제 URL 3~5개 | 대표 페이지의 접근·추출·근거 보존을 검증한다. |
| 정답 가격 표본 | 금액, 통화, 세금, 배송, 회원가 처리의 검증 기준으로 쓴다. |
| 비식별 내부 CSV/PDF 및 승인 접근 경로 | 내부 자료의 파일 매핑 또는 권한 범위를 설계한다. |
| 가격 정의 | `price_basis`, 포장 수량, 단가 계산, 가격 유형의 업무 의미를 정한다. |
| Claude Desktop/ChatGPT 대상 환경 | MCP 연결과 배포·다운로드 경로를 결정한다. |

OCR, 설정 출처 밖 검색 확대, 사내 ERP 연결은 필요한 자료와 권한·접근 설계가 마련된 경우에만 후속 범위로 검토합니다.

## 다음 개발 우선순위

1. 대표 출처 3~5개에서 SKU·옵션·가격 기준·세금·수량을 원문과 대조해 출처별 설정을 고정한다. 웹 페이지가 실제로 차단되는지, 로그인 세션이 재사용되는지는 이 단계에서 확인한다.
2. 새 출처를 추가하는 초기 설정 보조 기능을 만든다. AI는 선택자와 클릭 절차의 후보를 제안하고, 확인된 가격 표본을 통과한 규칙만 활성화한다. 반복 실행 때 같은 규칙을 재사용한다.
3. 독립 worker의 서비스 운영, 재시작, 예약 수집, 인증 만료·페이지 변경 알림을 추가한다. 현재의 작업 재개와 주기적 자동 실행은 별개다.
4. 대상 클라이언트에서 자체 MCP의 인증과 XLSX 전달을 검증한다. 유료 UWS 연결 없이 먼저 진행할 수 있다.
5. 자체 브라우저 수집으로 해결되지 않는 출처가 남을 때 UWS를 소량 비교 평가한다. 클라우드로 보낼 수 없는 내부 자료는 로컬 경로를 유지한다.

UWS 공식 문서는 기성 수집 작업과 이미 만든 scraper의 실행을 지원한다고 설명한다. 임의 사이트의 클릭 방식 scraper는 확장 프로그램에서 만들어야 하며, MCP 자체가 사용자의 열린 탭·로컬 파일을 읽지는 않는다. 이 서비스의 서버 코드를 검토하거나 실제 유료 MCP를 연결한 것은 아니다. [공식 설명](https://ultimatewebscraper.com/claude)
