# 수집 정확성 개선

[English](CROSS_SITE_RELIABILITY_2026-10-14.md)

[2026-10-14 검토](COLLECTION_AUDIT_2026-10-14.ko.md)에서 확인한 정확성·실행 제한 관련 개선을 반영했다. 임의의 사이트 전체를 빠짐없이 수집한다고 보장하는 변경은 아니다.

## 결과 판정

- 페이지 접속 성공과 전체 상품·옵션 확인을 구분한다. 범위를 검증할 수 없는 페이지는 `unknown`, 탐색·추출 한도 도달이나 실패·최종 원장 불일치는 `partial`로 기록한다.
- 추출 결과를 최종 SQLite 원장과 대조한다. 행 위치뿐 아니라 원본 값·규격·원본 SHA-256까지 일치해야 하며, 명시적으로 제외한 항목은 별도로 반영한다.
- MCP 작업 요약·UI·XLSX에 확인 불가와 부분 수집을 표시한다. 구역 정보가 없는 이전 결과도 포함한다. 인식한 구역의 완료가 사이트 전체 완료를 뜻하지 않는다.
- JSON-LD 파서를 통합하여 상품 옵션과 명시된 수량별 가격·규격을 보존한다. 가격 범위와 배송·결제 수수료를 상품의 확정 가격으로 바꾸지 않는다. 메타데이터는 검토 대상이다.
- 페이지 전체의 상품·제안·가격 명세·결과 후보에 상한을 적용하고 초과 사실을 기록한다. 링크 탐색의 1,000개 제한도 표시한다. 모든 사이트의 페이지 이동을 자동 해결하는 기능은 아니다.
- 제트카 화물 경로를 발견·추출 양쪽에서 지원한다. 렌트 표의 기간·가격·보증금·주행거리별 행을 확인한다.
- 브라우저에서 추가한 의류 크기·색상, 부품 규격, 포장·수량별 증거가 기존 상품 뒤에 가려지지 않도록 구별 가능한 옵션을 검토 후보로 표시한다.

## 재개와 실행 최적화

추출·검증·범위·보고서 코드가 변경된 체크포인트를 재개하면 저장된 원본을 새 실행 결과로 재분석한다. 완료된 페이지를 다시 방문하지 않으며, 이전 체크포인트·보고서·원본 수집 시각은 보존한다. **과거 원본의 재분석이며 최신 가격 수집이 아니다.** 미완료 작업의 남은 페이지는 방문이 필요할 수 있다.

체크포인트는 페이지별 불변 레코드를 참조하여 진행 상황을 저장할 때 이전 본문 전체를 반복 직렬화하지 않는다. HTTP 작업은 끝나는 순서대로 처리하고 최종 결과는 승인한 목록 순서로 정렬한다. robots 판정은 수집 작업 안에서만 제한적으로 캐시한다. 기존 브라우저 재사용·동시성 설정은 명시적으로 유지한다.

HTTP·Chromium의 리다이렉트 목적지는 방문 전에 URL·robots 정책을 확인한다. Chromium은 같은 탭에서 다음 주소로 이동하여 실제 최종 주소·상대 링크·`sessionStorage`·`window.name`을 유지한다. 이동 단계가 실패하면 수집 성공으로 처리하지 않는다.

브라우저 실행 파일 발견과 실제 실행 성공을 구분한다. 실행을 직접 확인하려면 다음 명령을 사용한다.

```console
source-ledger doctor --verify-browser-launch --browser-display-mode headless
source-ledger doctor --verify-browser-launch --browser-display-mode visible
```

브라우저 시작 실패는 `browser_launch_failed`로 구분한다. 요청한 표시 모드를 자동으로 창 없는 모드로 바꾸지 않는다.

## 검증과 남은 범위

회귀 테스트에는 상품 옵션, 가격 구간, 원본·장부 불일치, 탐색 한도, 체크포인트 재분석, UI·XLSX 범위 표시를 포함합니다. 저장 캡처 재생은 현재 사이트 목록이나 실시간 수집 속도를 증명하지 않습니다. 일반 사이트의 상호작용 옵션과 전체 경계는 검토된 레시피가 필요합니다. 브라우저 실행 가능 여부는 요청한 표시 모드에서 확인해야 합니다.
