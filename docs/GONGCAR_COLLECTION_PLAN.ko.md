# 공카 전체 목록 수집 수정 계획

상태: 2026-10-12 구현 및 실제 수집 검증 완료. 아래 기존 계획의 수치는 당시 관찰 기록입니다.

## 구현·실수집 결과

최종 실행에서 **공개 상품 88건·현재 가격 88건을 19.12초**에 수집했습니다(SQLite·XLSX 생성 포함). 렌트패스 인기 18·특가 3, 장기렌트 인기 64·특가 3입니다. 별도 브라우저에서 더보기를 각각 4회·15회 눌러 종료를 확인하고, 네 영역의 상품명·현재 가격을 중복 건수까지 대조해 모두 일치했습니다. 특가 영역에는 각 3개 카드가 있고 추가 페이지·넘침 영역이 없었습니다. 장기렌트 특가 3개의 원가도 현재가와 분리했습니다.

기존 121건은 과거 관찰이며 목표 건수로 고정하지 않습니다. 현재 목록과 달라진 원인은 이번 검증으로 확정할 수 없습니다. 완료 범위는 이 네 공개 영역이며, 한달·하루렌트, 비공개 재고, 모든 견적 조합을 포함하지 않습니다. 계약 조건이 부족한 가격은 계속 검토 대상으로 유지합니다.

더보기 반복, 이미지 없는 카드, 동일 차종·원본 ID의 별도 상품 보존, 보증금·선납금 분리, 누락 상태 표시, SQLite 커버리지, XLSX 재생성, MCP·UI 결과 연결을 구현했습니다. DOM·스크린샷·수집 기록은 Git 제외 로컬 결과에 보존합니다. 수집에 유료 모델 API는 사용하지 않았습니다.

검증: 백그라운드 브라우저 설정에서 전체 테스트 424개 통과·1개 건너뜀. 이후 최종 파서·설정 재사용 수정에 관련 회귀 테스트를 추가 실행했습니다. 합성 97개 목록·더보기 24회도 통과했습니다. 이 PC에서는 창을 띄우는 Chromium이 `spawn UNKNOWN`으로 시작되지 않아 `SOURCELEDGER_HEADLESS=1`로 실수집했습니다. 백그라운드 수집과 별도 인앱 브라우저 검증은 성공했으며, 창 모드 실행 문제는 환경상 제한으로 남습니다.

최종 로컬 실행 ID: `abaacf7285fd4819aeff9da78a170f5f`. 저장 설정으로 XLSX를 재생성한 뒤에도 네 영역의 커버리지 시트가 유지됐습니다. 실제 조사 자료는 커밋하지 않습니다.

마지막 회귀 검증에서는 관련 테스트 81개가 통과했고, 97개 합성 목록만 테스트 전용 10초 제한으로 76개에서 부분 수집 처리됐습니다. 완료 테스트 예산을 실제 수집과 같은 120초로 조정했으며 별도 시간 제한 테스트는 유지했습니다. 이후 브라우저 테스트 재실행에서는 Chromium 시작 불가로 브라우저 사례가 건너뛰어졌습니다. 따라서 마지막 브라우저 테스트 전체 통과를 주장하지 않으며, 앞선 전체 테스트·실수집 성공과 이 환경 제한을 구분합니다.

## 실제 검증 결과

| 영역 | 현재 확인한 상품 항목 | 확인 방법 |
|---|---:|---|
| 저신용 인기 상품 | 18 | 더보기 4→8→12→16→18, 마지막 버튼 소멸 |
| 저신용 프로모션 | 3 | 표시 카드 확인 |
| 일반 장기렌트 인기 상품 | 97 | 반복 확장 후 92→96→97, 버튼 소멸, 카드 내용 97개 모두 구별됨 |
| 일반 프로모션 | 3 | 정상가·할인가가 함께 표시된 카드 확인 |
| 합계 | **121** | 고유 차종 수나 확정 견적 수가 아닌 표시 상품 항목 수 |

이전 68개(일반 인기 43개·프로모션 4개 포함)는 현재 전체 수량으로 사용할 수 없습니다. 당시 집계 누락인지 사이트 변경인지는 현재 자료만으로 확정할 수 없습니다. 68개나 121개를 코드에 고정하지 않습니다. 구현 검증에서는 프로모션 영역의 가로 넘김·숨은 카드 여부도 별도로 확인해야 합니다. 범위는 `/rentpass`, `/longterm`이며 한달·하루렌트 등 다른 서비스는 포함하지 않습니다.

현재 브라우저에서 일반 장기렌트는 제목이 먼저 나타난 뒤 상품이 로딩됐습니다. 상품과 무관한 더보기 버튼도 있었고 넓은 영역 선택은 중복 일치했습니다. 따라서 제목 표시만 기다리거나 전역 첫 번째 더보기 버튼을 누르는 구현은 부정확합니다. 긴 브라우저 확인 호출 한 번이 도구 시간 제한에 걸렸지만 기존 페이지에서 이어서 목록 종료를 확인했습니다. 이를 사이트 접근 차단으로 해석하지 않습니다.

관련 기존 테스트 **60개 통과(13.41초)**: `test_site_adapters.py`, `test_site_collection.py`, `test_catalog_collection.py`, `test_incremental.py`. 샌드박스의 파일·레지스트리 제한으로 중단된 테스트는 허용된 실행 환경에서 다시 확인했습니다. 기존 테스트 통과는 전체 목록 수집 기능이 있다는 뜻이 아닙니다. 테스트용 저신용 fixture의 카드 3개는 실제 사이트 수집 제한이 아닙니다.

## 수정 순서

1. **완료 판정부터 정의**: 페이지 방문, 목록 확장 완료, 가격 추출, 계약 조건 검증을 분리합니다. 영역별 발견 상품·추출 상품·숫자 가격·미해석 항목 수와 종료 근거를 저장합니다. 영역이 안 보이면 빈 목록이 아니라 미확인으로 처리합니다.
2. **더보기 반복 기능**: `collectors.py`에 제한 있는 반복 확장을 추가하고 `site_collection.py`에서 상품 영역에만 적용합니다. 상품 실제 로딩, 클릭 후 증가, 종료를 확인합니다. 무응답·시간 초과·영역 중복은 부분 수집으로 남깁니다. 이전 카드가 사라지는 가상 목록이면 각 배치의 증거를 누적합니다. 상담 버튼은 누르지 않습니다.
3. **네 영역 추출**: `adapters/gongcar.py`에 일반 카드·프로모션 지원을 추가합니다. 보증금과 선납금, 정상가와 할인가, 시작 가격을 분리합니다. 금액 역할이 불명확하면 임의로 작은 금액을 선택하지 않습니다. 동일 차명이 여러 번 나와도 다른 상품을 합치지 않으며, 자체 식별자는 판매자 공식 식별자와 구분합니다.
4. **증거·출력 연결**: 확장된 원문·화면·클릭별 개수·종료 사유를 SQLite와 보고서에 연결합니다. MCP·웹 UI·XLSX가 같은 영역별 완료 상태를 표시하도록 합니다. 영어·한국어·일본어 문구를 함께 반영합니다. 중단 후 재개와 레시피 버전 변경도 처리합니다.
5. **검증 후 재측정**: 오프라인 동적 목록 테스트 → 저장·MCP·UI·XLSX 통합 테스트 → 두 URL 실제 수집과 독립 브라우저 목록의 상품별 대조 순서로 진행합니다. 정확성을 확인한 뒤 구독 모델 MCP 실행을 점검하고, 필요할 때 네 모델의 장시간 벤치마크를 다시 실행합니다.

## 회귀 테스트와 완료 조건

- 더보기 정상 종료, 초기 로딩 지연, 클릭 무응답, 시간 제한, 다른 영역 더보기, 상품 교체형 목록을 검증합니다.
- 동일 차명·다른 가격, 선납금/보증금, 정상가/할인가, 조건 누락, 레이아웃 변경을 검증합니다.
- 부분 수집이나 가격 누락을 전체 완료로 표시하지 않아야 합니다.
- 화면에 발견한 모든 상품에 **가격·조건·출처 또는 미수집 사유**가 남아야 합니다. 없는 수치는 기록하지 않습니다.
- 목록 전체 발견과 확정 견적 검증은 별개입니다. 계약 조건 부족 시 기존 review 상태를 유지합니다.
- 과거 수량이 아니라 실행 당시 목록 종료와 개별 상품 대조로 판단합니다. 비공개 재고 전체를 확보했다고 주장하지 않습니다.

주 에이전트가 데이터 계약·통합·검수를 맡고, 브라우저 확장과 영역별 추출은 파일 소유권이 겹치지 않도록 Sol 작업으로 나눕니다. UI·문서는 데이터 계약이 정해진 후 진행합니다. 아직 제품 코드 수정·커밋·푸시는 하지 않았습니다.

자세한 담당 파일, 필드 설계, 캐시·재개·증거 처리, 미확정 확인 사항은 [영문 계획](GONGCAR_COLLECTION_PLAN.md)에 기록했습니다.
