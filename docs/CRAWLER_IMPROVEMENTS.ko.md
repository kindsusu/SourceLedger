# GitHub 구조 검토를 반영한 수집 개선

2026-10-13, [Exa MCP·Scrapy 검토](UPSTREAM_ARCHITECTURE_REVIEW.ko.md)에 따라 기존 SourceLedger에 필요한 기능을 적용했습니다. 두 프로젝트로 엔진 전체를 교체하지 않았습니다.

## 적용한 기능

- **실제 병렬 수집:** 새 웹 UI·MCP 조사 작업의 기본값은 동시 2개입니다. 실행 전 1~4개를 선택하며 계획 표시와 실제 작업에 같은 값을 전달합니다. 직접 `collect_plan`을 호출하거나 이전에 준비된 작업을 재개하면 기본 1개를 유지합니다.
- **사이트별 제한:** 병렬 모드는 HTTP 요청을 동시에 처리합니다. HTTP와 브라우저가 전체 한도·사이트당 최대 2개 제한을 공유하고, 같은 사이트의 요청 시작 사이에 0.25초 간격을 둡니다. 브라우저는 조정자가 한 번에 1개씩 처리합니다. 체크포인트·원장 쓰기도 한 곳에서 수행합니다.
- **제한된 재시도:** HTTP 429·5xx·시간 초과·통신 오류만 시간 예산 내에서 HTTP를 한 번 추가 시도합니다. 인증·정책 거부는 자동 재시도하지 않습니다. 같은 사이트 작업끼리 대기를 공유하며, 유효한 `Retry-After` 대기 시간을 임의로 줄이지 않습니다. 대기 시간이 길면 이번 작업의 시간 한도에 도달할 수 있습니다. 순차 모드는 기존 실행 경로를 유지합니다.
- **복구 가능한 페이지 큐:** URL과 쿼리, 상태, 시도 횟수, 임대 시작·만료 시각을 SQLite에 기록합니다. 재개할 때 실제 캡처 체크포인트와 대조합니다. 저장되지 않은 진행 중 페이지는 중단으로 표시하고 명시적으로 재시도해야 합니다. 대기 페이지는 이미 사용한 페이지·시간 예산을 보존하며 이어갑니다. 임대 만료만으로 자동 재수집하지 않습니다.
- **작은 MCP 진행 응답:** `get_research_progress`로 대기·진행·완료·검토·실패 건수와 보고서 준비 상태를 확인합니다. HTML·스크린샷·전체 관측값은 반환하지 않습니다. 상세는 기존 페이지 단위 조회 도구로 읽습니다. 페이지 처리 완료는 가격 검증 완료를 의미하지 않습니다.
- **선택적 Exa 연결:** 연결된 AI 앱이 이미 조회한 Exa 결과를 `prepare_external_discovery`로 검증 전 후보로 정리할 수 있습니다. SourceLedger가 Exa를 호출하거나 유료 서비스를 활성화하지 않습니다. [연결 방법과 한계](EXTERNAL_DISCOVERY.ko.md)를 참고하세요.
- **저장 최적화:** [체크포인트 저장 개선](STORAGE_OPTIMIZATION.ko.md)도 함께 적용되어 원본 바이트를 유지하면서 반복 저장을 줄입니다.

Codex에서는 Sol, Claude에서는 Opus 추천을 유지합니다. 두 모델을 동시에 실행하는 기능이 아니며, 병렬 수집 때문에 모델 API를 추가 호출하지 않습니다.

## 검증과 체감 효과의 범위

오프라인 테스트로 HTTP 동시 실행, HTTP·브라우저 합산 한도, 사이트별 대기, 일시 오류 재시도, 중단 후 복구 예산, UI·MCP 설정 전달, 실제 실행 중 진행 건수, Exa 결과의 미검증 상태 보존을 확인합니다.

저장된 제트카 6개·공카 6개 페이지의 같은 응답을 순차·병렬로 재생해 **12개 URL·44개 관측값의 가격·원문 조건·필드 근거 일치**를 확인했습니다. 각 모의 조회에 0.30초를 넣은 검증이므로 실제 사이트 속도 측정이 아닙니다. 브라우저 처리·보고서 작성은 순차이므로 이전 독립 작업 공간 2개 실험의 단축률을 이번 구현에 적용하면 안 됩니다.

저장 복사본 실측에서는 전체 보관량 환산 21.37%, 체크포인트 저장 시간 75.22% 감소를 확인했습니다. 이후 실제 구독 실행 결과는 [수집 성능](COLLECTION_PERFORMANCE.ko.md)에 기록합니다. Exa 검색 품질·비용·차단 페이지 접근 성능은 아직 측정하지 않았습니다.

과거 실측 문서는 당시 구성을 기록한 자료입니다. 기존 수집 원본을 덮어쓰지 않았고 외부 유료 서비스를 활성화하지 않았습니다.

초기 전체 회귀 검증은 headless 브라우저 테스트를 포함해 **477개 통과·1개 건너뜀**이었습니다. 저장된 12개 URL 재생에서는 44개 관측값이 일치했습니다. 해당 오프라인 검증 중 실제 대상 사이트나 모델 API를 호출하지 않았습니다.

이후 [서버 배치 기능](SERVER_BATCH_COLLECTION.ko.md)으로 배치마다 AI 계획·승인을 반복하는 과정을 없애고 배치별 체크포인트와 보고서를 유지했습니다. 동적 목록은 0.4초 확인 대신 버튼 부재와 카드 내용의 안정성을 확인합니다. 목록 확장 브라우저 테스트 14개, 관련 배치·MCP·런타임 테스트 51개가 통과했습니다. 확장된 전체 테스트는 489개 통과·1개 건너뜀·기존 UI 워커 시작 테스트 1개 실패였고, 실패 항목은 이후 단독 재검증에서 통과했습니다. 간헐 실패 원인은 아직 확정하지 못했으므로 전체 테스트가 모두 통과했다고 표현하지 않습니다.
