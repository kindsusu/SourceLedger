# CI 및 릴리즈 검증

`Tests`는 푸시와 PR에서 Ubuntu/Python 3.11·3.12·3.13, Windows/Python 3.12, macOS/Python 3.12를 검사합니다. 별도 작업이 배포 파일을 만들고 설치합니다. **All environments passed**는 모든 테스트 환경과 배포 검사가 성공해야 통과합니다. 취소되거나 건너뛴 작업도 통과로 취급하지 않습니다.

각 테스트 환경의 JUnit 결과와 실행 환경·패키지 버전을 단기 보관 아티팩트 `test-diagnostics-*`에 저장합니다. 진단 픽스처를 사용하는 브라우저 테스트가 실패하면 화면 캡처와 Playwright trace도 저장합니다. CI에서는 비공개 조사 대상을 수집하지 마세요. 조사 워크스페이스, 브라우저 프로필, 쿠키, 인증정보, 수집 문서를 업로드해서는 안 됩니다.

완료를 보고하기 전에 **그 커밋의** `Tests` 실행에서 **All environments passed**가 성공했는지 확인합니다. 로컬 테스트만으로 운영체제별 실패 여부는 확인할 수 없습니다.

코드 수정은 `claude/` 또는 `codex/` 브랜치와 PR로 진행합니다. 필수 검사 통과와 사용자의 명시적 승인 후 병합하고, 병합된 커밋의 `main` CI까지 확인합니다. 릴리즈는 해당 커밋의 최신 `main` CI가 통과한 뒤 새 버전 태그를 만들고 **Verified release**를 수동 실행해 태그를 입력합니다. 릴리즈 작업은 태그가 가리키는 정확한 커밋에서 **가장 최근의** `main` 푸시 기반 `Tests`를 확인합니다. 더 최근 실행이 진행 중·취소·실패 상태라면 과거 실행이 통과했어도 게시를 거부합니다. 최신 실행의 집계 검사가 통과해야 동일 실행의 배포 파일을 받아 태그 버전과 대조한 뒤 게시합니다. 릴리즈 시 재빌드하지 않으며 일반 푸시만으로 게시하지 않습니다.

현재 활성화된 규칙은 `main` 반영에 PR, 최신 main 반영, GitHub Actions의 5개 환경·패키지·집계 검사 통과를 요구합니다. 관리자 우회, 강제 푸시, 브랜치 삭제는 금지됩니다. `v*` 태그도 생성 전 동일한 검사 통과를 요구하고 생성 후 변경·삭제를 금지합니다. [main 보호](https://github.com/kindsusu/SourceLedger/rules/25197414)와 [릴리즈 태그 보호](https://github.com/kindsusu/SourceLedger/rules/25197544)를 참고하세요. 소유자가 규칙 자체를 변경하거나 기존 태그로 수동 릴리즈를 게시하는 행위까지 막지는 못하므로, 게시에는 **Verified release**를 사용합니다.
