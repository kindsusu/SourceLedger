# CI and release checks

The `Tests` workflow runs on pushes and pull requests. Its matrix covers Ubuntu with Python 3.11, 3.12, and 3.13, plus Windows and macOS with Python 3.12. A separate job builds and installs the wheel. **All environments passed** succeeds only when the full matrix and package job succeed; a cancelled or skipped dependency also fails the gate.

Each matrix job saves JUnit output and runtime/package versions as a short-lived `test-diagnostics-*` artifact. Browser tests that opt into the shared diagnostic fixture add a screenshot and Playwright trace when they fail. The artifacts are for test fixtures only; do not run collection against private research sources in CI or upload research workspaces, profiles, cookies, credentials, or collected documents.

Before declaring a commit complete, inspect the `Tests` run for that exact commit and wait for **All environments passed**. A local suite passing is insufficient when the failure is platform dependent.

Deliver changes through a `claude/` or `codex/` branch and pull request. Wait for all required checks and the user's explicit approval before merging, and verify the merged commit's `main` CI. To publish a version, wait for the release commit's latest `main` CI to pass, then create its new version tag. Manually dispatch **Verified release** with that tag. The release workflow resolves the tag to an exact commit and checks the **latest** `main` push-triggered `Tests` run for that commit. An in-progress, cancelled, or failed newer run blocks release even if an older run passed. The latest run must succeed with the aggregate gate. The workflow downloads distributions from that same run, checks their filenames against the tag version, and publishes the release. It does not rebuild at release time or publish on ordinary pushes.

Active repository rules require a pull request, an up-to-date branch, all five environment checks, the package check, and **All environments passed** from GitHub Actions before updating `main`. Administrator bypass, force pushes, and branch deletion are disabled. The `v*` tag rules require the same checks before creation and prohibit tag updates and deletion. See [main protection](https://github.com/kindsusu/SourceLedger/rules/25197414) and [release tag protection](https://github.com/kindsusu/SourceLedger/rules/25197544). These rules do not prevent an owner from changing the rules or publishing a manual release against an existing tag; use **Verified release** for publication.
