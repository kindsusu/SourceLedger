# 수집 한계 대응 구현 검토 — 2026-10-14

[English](LIMITATION_IMPLEMENTATION_REVIEW.md)

## 반영 내용

- URL별 수집 규칙을 계획·MCP·웹 UI·실행 미리보기에 연결했다. 수정하면 기존 승인이 해제된다.
- 기본 선택 상자의 종속 옵션, 검토한 옵션 버튼, 페이지 이동, 누적 스크롤을 제한된 범위에서 순회한다. 이전 페이지의 링크와 상태별 HTML을 보존한다. 정체·목록 교체·상한 도달을 전체 완료로 처리하지 않는다.
- 가격 행에 해당 시점의 원본·선택 라벨/값·시각·해시를 연결한다. 실패 전 캡처는 별도 증거로 보존하고 이슈·엑셀에서 찾을 수 있게 했다. 실패한 수집에서 가격을 만들어내지 않는다.
- 권한 있는 기존 프로필을 명시적으로 사용한다. 인증·정책·브라우저 환경·일시 오류·상한·범위 미확인을 구분해 다음 조치를 안내하고 재시도 횟수를 제한한다.
- SQLite 문제 원장에 상태 변경 이력을 누적한다. 이후 실행의 같은 범위가 검증돼야 해결 처리한다. 규칙·계획 변경은 지문 변경과 검토 사유를 기록하며 과거 수집 범위는 바꾸지 않는다.
- 완료된 조사·배치 작업의 문제 목록을 MCP와 영문·국문·일문 UI에서 조회한다. 엑셀은 상태 변경·재출력 시 최신 문제 원장을 사용한다. 파일이 열려 갱신할 수 없으면 DB 저장 성공과 엑셀 갱신 대기를 구분해 안내한다.

## 검증 방법

오프라인 회귀 테스트와 저장 캡처 재생으로 섹션 범위, 문제 처리, 증거 연결을 확인합니다. 미완료 페이지는 검토 대상으로 표시합니다. 재생은 새 사이트 방문이 아니므로 현재 목록이나 수집 속도를 증명하지 않습니다. 동작 변경 후 관련 브라우저·UI·후속 처리·문제·파이프라인·리다이렉트 테스트를 실행합니다.

## 남은 운영 한계

새 사이트는 화면 확인과 수집 규칙 검토가 필요하다. 임의의 맞춤 컨트롤·가상 스크롤·총목록 근거가 없는 사이트를 무조건 완료 처리하지 않는다. 준비 표시만으로 가격 갱신을 확정할 수 없어 옵션 후보는 검토 상태로 남긴다. CAPTCHA·로그인·내부 접근 권한에는 사용자 조치가 필요할 수 있으며 AI 앱의 브라우저를 자동 제어하지 않는다.

브라우저 검증은 헤드리스 모드로 진행했다. 이전의 화면 표시 모드 실행 실패가 해결됐다는 뜻은 아니다. 이번에는 신규 실사이트 전체 수집, 모델별 성능·토큰 비교를 수행하지 않았다. 사용법은 [수집 한계와 재처리 관리](LIMITATION_MANAGEMENT.ko.md)를 참고한다.
