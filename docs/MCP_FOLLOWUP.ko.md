# MCP 근거 보완과 조사 재개

연결된 AI 앱에서 조사 요청을 시작합니다. AI가 사용할 수 있는 검색·브라우저로 계획을 제안하고, 사용자가 범위를 확인한 뒤 수집합니다. 별도 하위 모델이나 유료 스크래핑 서비스는 이 흐름의 필수 조건이 아닙니다. 브라우저 제공 여부와 모델 사용량은 연결한 AI 환경을 따릅니다.

`start_research_plan` 완료 후 다음 순서로 진행합니다.

1. `get_research_gaps(job_id, offset=0, limit=50)`로 실패·미처리 페이지와 미확인 조건을 조회합니다. 이 호출은 웹 검색이나 모델 호출을 하지 않습니다. 페이지 방문과 가격 검증 완료는 다릅니다.
2. 재시도 가능한 실패는 `retry_research_pages(job_id, urls, max_seconds=120)`로 처리합니다. 같은 승인 계획의 기존 미해결 URL만 허용하며, 인증·정책 거부와 이미 추출된 검토 대기 가격은 무조건 재시도하지 않습니다. URL당 1페이지, 최대 50페이지·600초의 **새 한도**를 명시적으로 시작합니다. 새 링크를 확장하지 않고 완료 페이지의 저장 자료를 재사용해 종합 보고서를 만듭니다. 실행별 이력은 별도 보존합니다.
3. AI의 브라우저에서 직접 확인할 수 있으면 `submit_browser_evidence`로 근거를 제출합니다. 실제 상품·옵션 영역을 확인한 뒤 `job_id`, 승인 범위의 `url`, 시간대가 있는 ISO 시각 `captured_at`, `page_text`, `fields`, `locator`를 전달합니다. `fields.name`은 필수이며, 없는 가격·통화·조건은 생략합니다. 모든 값은 제출한 원문에 그대로 있어야 합니다. 상품·옵션별로 제출하며 계약 기간도 구분합니다.
4. `get_job_observations`와 `get_job_report`로 결과와 XLSX 리소스를 확인합니다. 브라우저 제출 자료는 SQLite·웹 UI 관측치 목록·갱신된 XLSX에 검토 대기로 표시됩니다.

선택 항목 `screenshot_path`는 워크스페이스 내부의 상대 경로 PNG이며 최대 10 MiB입니다. AI가 제출한 원문·화면과 상품별 값의 연결은 아직 독립적으로 검증된 자료가 아닙니다. 문자열 일치가 페이지 진위나 화면 표시, 올바른 옵션 연결을 증명하지 않습니다. 따라서 제출 즉시 검증 완료·직접 비교 가능으로 승격하지 않습니다. 기존 가격·날짜·조건 검사는 적용하고, 미확인 값은 누락 또는 검토 대기로 남깁니다. 동일 제출은 중복 저장하지 않으며, 부분 재시도 후에도 보완 자료 이력을 보존합니다.

**중단된** 계획 수집은 `resume_job_execution(job_id)`로 재개합니다. MCP 호출이 워커를 시작하며, SQLite 체크포인트에 완료 페이지·대기열·승인 범위·사용한 한도를 유지합니다. 완료 페이지는 다시 수집하지 않습니다. 페이지 처리 중 프로세스가 종료되면 예약한 페이지·시간을 보수적으로 사용 처리하고 해당 페이지를 중단 항목으로 남겨 명시적으로 재시도하게 합니다. 재개로 한도가 초기화되지는 않습니다. AI 미리보기와 체크포인트가 없는 구버전 계획 작업은 새 실행이 필요합니다.

웹 UI와 MCP가 같은 자료를 보려면 동일 워크스페이스를 사용해야 합니다. MCP가 다른 앱의 대화를 자동 실행하지는 않습니다. 브라우저 근거 제출은 MCP 기능이며 새 UI 업로드 폼이 아닙니다. 실제 브라우저 조작은 연결된 AI가 수행합니다.

조사 범위는 선택·방문한 페이지까지입니다. 제트카에서는 로그인·약관·회사소개 대신 차량 상세 링크를 탐색합니다. 사이트의 모든 차량·옵션을 수집했다는 의미는 아닙니다.

## 가격 결과와 보완 근거 구분

`get_job_observations.rows`는 수집 결과를 반환하며 브라우저 근거를 추가 가격으로 집계하지 않습니다. 결과별로 `field_status`, `missing_conditions`, `supporting_evidence`, `conflicts`를 제공합니다. URL·상품명·제출된 옵션 식별값(계약 기간 등)이 유일하게 일치할 때 근거를 연결합니다. 연결이 불분명하거나 일치하지 않으면 `evidence_submissions`에 별도로 남깁니다. 연결은 가격 검증 완료가 아니며, 값이 충돌하면 양쪽 값을 표시하고 직접 비교에서 제외합니다. 보완 근거로 원본 값을 덮어쓰거나 누락값을 채우지 않습니다.

XLSX의 첫 시트 **Results**에서 가격·수집 조건·미확인 조건·연결 근거 수를 확인합니다. **Supporting Evidence**에는 연결 대상 또는 미연결 상태를 표시하며, **Rental Quotes**에는 수집 결과만 남깁니다. **Observation History**와 **Source Evidence**에는 원본 기록을 모두 보존합니다. 웹 UI도 같은 건수와 펼쳐볼 수 있는 근거, 항목별 수집됨·미확인·충돌 상태를 영어·한국어·일본어로 보여줍니다. ‘수집됨’은 값이 기록됐다는 뜻이며 최종 계약 견적을 검증했다는 뜻은 아닙니다.
