# 한 번 승인한 전체 목록 수집

검토한 URL 목록을 한 번 승인하면 서버 작업 하나가 배치를 이어서 처리합니다. 연결된 AI 앱은 계획과 결과 검토를 맡고, 배치마다 계획 생성·승인을 반복하지 않습니다.

## MCP 사용 순서

1. 조사계획을 만들고 `update_research_plan`으로 정확한 URL 목록을 추가합니다. 명시적인 목록은 최대 1,000개이며 AI 미리보기 제안은 기존 100개 제한을 유지합니다.
2. `get_research_batch_execution_plan`으로 사이트, URL 수, 배치 수, 배치별 제한을 확인하고 연결된 AI 모델과 함께 사용자에게 설명합니다.
3. `confirm_research_plan`으로 해당 계획 버전을 한 번 승인합니다.
4. `start_research_batch_run`을 실행합니다. 기본값은 배치당 20 URL·600초·HTTP 동시 수집 2개이며 추가 링크 탐색은 하지 않습니다.
5. 작업을 기다리고 `get_research_batch_progress`, `get_research_batch_reports`로 진행 상황과 배치별 엑셀을 확인합니다.

승인된 계획과 URL 순서는 고정됩니다. 배치마다 체크포인트와 보고서가 있고, 계획의 SQLite와 증거 폴더를 공유합니다. 기존 단일 계획 수집의 제한은 유지하며 브라우저 수집은 한 번에 하나씩 진행합니다.

완료된 배치는 서버 진행 기록에 저장됩니다. 중단 작업을 명시적으로 이어받으면 완료 배치를 건너뛰고 현재 배치의 체크포인트와 남은 예산을 사용합니다. 부분 수집으로 끝난 배치를 몰래 재수집하지 않습니다. 중지 요청은 배치 사이에서 확인하므로 진행 중인 배치의 남은 제한 시간만큼 기다릴 수 있습니다.

## 누락과 근거 확인

작업 실행 성공과 URL 방문 성공은 전체 상품 수집 보장이 아닙니다. 섹션 완료 여부, 누락 페이지, 관측 행 수, 원본 근거를 별도로 확인해야 합니다. 근거 없는 값은 채우지 않으며 계약 조건 검토도 필요합니다.

더보기 버튼이 사라져도 설정된 진행 대기 시간 동안 버튼 부재와 카드 목록의 안정성을 확인합니다. 버튼이 다시 나타나면 기존 클릭·시간 제한 안에서 확장을 계속합니다. 확인 시간이 부족하면 `completion_unconfirmed` 부분 수집으로 기록하고, 목록 자체가 교체된 경우에도 완료로 처리하지 않습니다. 사이트가 모든 상품을 공개했다는 보장이 아니라 정해진 시간 동안 화면 상태를 확인하는 방식입니다.

## 시간 비교

수집기 처리 시간과 AI 앱의 요청부터 최종 응답까지 시간을 구분합니다. 후자에는 계획·도구 호출·대기·정리가 포함됩니다. URL 순서, 배치 제한, 체크포인트 조건, 브라우저 동시성, 증거 보존 조건을 같게 맞춥니다. 모델을 변경했다면 시간 차이 전체를 코드 개선 효과로 판단하지 않습니다.

연결된 앱의 선택 모델을 사용하며 모델 API가 필수는 아닙니다. 실제 수집 결과와 원본 근거는 로컬에 보관하고 커밋하지 않습니다.
