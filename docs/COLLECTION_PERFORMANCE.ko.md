# 수집 시간 측정과 최적화

목록 탐색, 수집, 근거 검수, AI의 판단·도구 호출 시간을 따로 측정합니다. 속도가 빨라져도 URL·상품 조건·가격 근거·누락 검사가 같아야 유효한 개선입니다.

## 측정 범위

비교할 때 승인한 URL 목록, 페이지·시간 한도, 체크포인트, 증거 조건과 실행 환경을 고정합니다. 수집 시간과 AI 앱의 계획·도구 호출 시간을 구분합니다. 목록이 줄거나 미완료인 실행을 속도 개선으로 보지 않습니다.

## MCP 비교

새 작업 공간에서 같은 승인 목록으로 실제 stdio MCP 흐름을 실행합니다. URL 범위, 관측값과 조건, 체크포인트, 증거 해시를 비교합니다. 사이트별 실측 결과와 조사 자료는 Git 제외 로컬 작업 공간에 보관합니다.

## 구독형 AI 앱 비교

첫 요청부터 최종 답변까지 모델 계획과 도구 호출을 포함해 측정합니다. 선택한 구독 모델과 공급자가 실제로 보고한 토큰을 기록합니다. 세션 전체 토큰을 구간별 수치로 추정하지 않습니다. 같은 범위로 비교하고 실사이트 변경은 별도로 기록합니다.

## 적용 우선순위

1. **제한된 병렬 수집:** 같은 목록·체크포인트·캐시·스크린샷 조건에서 작업자 1개와 2개를 비교합니다. 도메인별 호출 간격, 재시도, 취소, 중단 복구 예산을 유지합니다. 차단이나 과도한 요청 응답이 나타나면 동시 수를 늘리지 않습니다.
2. **브라우저 재사용:** 선택 기능으로 작업자별 브라우저 프로세스를 유지하고 페이지마다 새 격리 컨텍스트를 만듭니다. 속도 효과는 사이트마다 같은 조건에서 확인해야 합니다. 프로필 분리·장애 복구·근거 보존을 검증합니다.
3. **체크포인트 저장 개선:** 캡처는 해시별로 한 번 저장하고 진행 상태를 별도로 갱신합니다. 구버전 읽기, 원자성, 중단 페이지의 예산 차감과 복구를 보존합니다. 체크포인트 쓰기 시간만으로 전체 수집 시간 단축을 주장하지 않습니다.
4. **중복 작업 줄이기:** 한 상세에 계약기간별 가격이 모두 보이면 한 번에 읽습니다. 변경 없는 근거의 재사용은 신선도·조건부 응답을 확인한 경우에만 허용합니다. 속도만을 이유로 HTTP나 브라우저를 생략하지 않습니다.
5. **전체 흐름 측정:** 수집 단계, 모델 판단, 도구 호출, 실제 제공된 토큰 사용량을 분리합니다. 수집기·MCP 직접 호출 시간에는 AI 모델 판단 시간이 포함되지 않으므로 구독형 AI 앱 결과와 혼동하지 않습니다. 제공되지 않은 단계별 토큰 수는 추정값으로 채우지 않습니다.

## 완료 기준

- 고정 URL 목록과 조회 조건을 비교하고 사이트 상품 변동은 따로 기록합니다.
- 행 수뿐 아니라 가격·조건 집합, 선언 수·관측 수·추출 수, 근거 방식도 대조합니다.
- HTML·receipt·스크린샷과 해시를 확인하고, 상업 조건이 불완전하면 검토 상태를 유지합니다.
- 성공 수집 시간, 실패·재시도 비용, 개발·검수 시간을 분리합니다. 나눠 실행한 시간 합계는 단일 연속 실행 시간으로 표현하지 않습니다.
- 이전과 범위·설정이 다른 실행으로 정확한 개선율을 주장하지 않습니다.

상품 목록·가격·데이터베이스·근거 파일은 Git에서 제외된 로컬 작업 공간에 보관합니다.

## 체크포인트 저장 개선 적용

체크포인트의 첫 저장 개선을 적용했습니다. 바이너리 캡처를 해시별로 한 번 저장하고 압축 효과가 있는 본문은 무손실 압축합니다. [체크포인트 저장 방식](STORAGE_OPTIMIZATION.ko.md)을 참고하세요. 제한적 HTTP 병렬 처리, 서버 배치, 선택적 브라우저 프로세스 재사용을 구현했습니다. 기존 실행 원본은 변경하지 않았습니다.

## 서버 배치 측정

확정한 URL 목록은 [서버 배치 흐름](SERVER_BATCH_COLLECTION.ko.md)으로 제한된 크기로 처리할 수 있습니다. 요청부터 답변까지의 시간, 수집 시간, MCP 호출, 증거 무결성, 모델 사용량을 나누어 기록합니다. 사이트별 실측 결과는 로컬 조사 기록에 남기며 일반적인 단축 효과를 주장하지 않습니다.
